哪些板子和元件能用？
屏幕画面
征辰 Wi-Fi、征辰 Wi-Fi＋ML307 的 r4 横屏固件支持局域网投影。ML307 版需切到 Wi-Fi。其他固件可实现相同的 JPEG 接口。只有串口日志的设备可在「板子状态」查看输出。
自动体检
通用串口、ESP32、MicroPython / CircuitPython REPL 和 BoardBenchProbe 各有检查方案。正点原子一代 BOX 的专用探针还能读取六轴、按键、I²C 应答和背光控制状态。
小智设备
征辰两款和 ESP32-S3 单麦 Wi-Fi 面包板有独立检查清单。收到相应日志时显示屏幕、音频、摄像头、天气、语音连接和 4G 模块记录。
扩展传感器
固件可按 BoardBench 遥测格式上报温度、湿度、气压等读数和器件型号。未上报的器件不会标为正常。

板子上各个部件的状态

这是什么：连上板子后，这里只“听”板子自己说的话，不会给它发任何东西。板子报告了哪个部件（屏幕、Wi-Fi、喇叭…），就列出哪个。 该怎么看：绿色“有读数 / 有应答”是正常；红色是板子自己报了错；“未上报”只表示固件没说，不代表坏了。点部件名能看它的原始记录。

刷固件

这是什么：把新的程序（固件）写进板子。每一步都先检查、先备份；Wi-Fi、音量这些设置默认不动；刷坏了可以一键恢复。 注意：刷写时别拔线、别关软件。看板子状态时软件只“听”不写，只有在这里点了按钮才会写板子。

    出问题了怎么办

    按你看到的情况，从上往下试。每一条后面的按钮会直接带你去对应的地方。

    列表里找不到我的板子 / 连不上
    1. 换一根能传数据的 USB 线（有些线只能充电），插紧。
    2. 关掉别的串口软件（Arduino 串口监视器、其他刷机工具），它们会占着端口。
    3. Windows：在“设备管理器”里看有没有带黄色感叹号的设备，有的话装板子 USB 芯片的驱动（常见 CH340、CP210x）。
    4. 点“重新找端口”。还不行就拔掉再插一次。
    板子一直重启、连上又断开

    有些板子（比如用自带 USB 口的 ESP32-S3）在电脑“打开”端口时会被重启。本软件已经用不会触发重启的方式打开端口；如果板子刚连上就断，软件会等一会儿再连，连续 3 次都这样就停下来，并在“板子状态”页说明原因。

    还是反复重启：换到板子上标着 UART 的那个 USB 口，或者看看是不是供电不够（换个 USB 口、别用延长线）。

    能连上，但屏幕、声音或按键不正常
    1. 先做“自动体检”，看哪个部件被标成“异常”，点后面的日志编号看原文。
    2. 在右边的记录里只看“出错”，常常能直接看到原因。
    3. 需要人一项一项确认的（看屏幕、听声音），用自动体检页最下面的“人工逐项检查”。
    刷完固件开不了机 / 刷坏了
    1. 每次刷写前软件都自动备份了。到“刷固件”页最下面的“以前的备份”，点“恢复这个备份”。
    2. 如果软件连不上板子：按住板子上的 BOOT 键，再按一下 RESET（或 RST）键，松开 BOOT，然后再点恢复。
    想请别人帮忙看看
    1. “导出报告”：TXT 给人看，JSON 是完整数据，表格（CSV）能用 Excel 打开。
    2. “分享故障记录”（在导出报告里）：只打包出错前后的内容，会先遮住密码、地址等敏感信息，你还能再删改。
    3. “AI 帮我看”：用你自己设置的 AI 分析，发送前会先给你看内容。

    检查项目

    给板子发命令

    这是什么：直接给板子发一段文字或数据，适合知道板子支持哪些命令的人。不知道发什么就不用这个页面。发出和收到的内容都会记在右边的记录里。

    写个备注

    记下用的什么线、怎么供电、按了什么键、看到了什么怪现象，导出报告时会一起带上。

    读数曲线

    这是什么：把板子最近输出的数字画成曲线（例如温度、电压）。板子要输出像 {"temp":23.5}、temp=23.5 或 1.2,3.4 这样的行，才有曲线。

    语音回声测试（小智）

    这是什么：检查小智板子的麦克风和喇叭：你对板子说话，电脑把声音原样传回去让板子播放。不用联网到云端。 要求：板子和电脑连同一个 Wi-Fi，固件允许改“OTA 地址”（WebSocket v1 协议）。

    步骤：① 先抄下板子原来的 OTA 地址；② 在板子的配网页面里临时换成上面的地址；③ 唤醒板子，说一串数字（最多录 3 秒），板子会把你的声音播回来；④ 测完把原地址改回去。

    声音清不清楚、屏幕字对不对，由你自己判断；右边的记录会写下每一步有没有成功。

    AI 帮我看

    这是什么：把这次记录里的错误和前后几行交给你自己配置的 AI 模型，请它帮忙分析原因。发送前一定先给你看要发出去的内容，确认后才发。
